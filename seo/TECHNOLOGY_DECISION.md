## القرار
**الإبقاء على Static HTML الحالي مع إضافة طبقة سكربتات تحقق/توليد، وعدم إعادة الكتابة الآن.**
الأسباب المرتبطة بالمشروع (لا بالحداثة):
1. الموقع يعمل بسرعة مثالية أصلاً ولا JS على الصفحات المُدارة؛ Rewrite لن يضيف سرعة.
2. GitHub Pages ثابت ولا حاجة لخادم؛ Static يحقق الهدف بأدنى تعقيد (§6).
3. لا Build حالياً ⇒ لا تبعيات ولا مخاطر كسر؛ إضافة Build تزيد سطح الصيانة بلا داعٍ الآن.
4. التحكم في SEO كامل يدوياً ومُتحقَّق منه آلياً (%100 على الحقول الأساسية).
5. الأتمتة الحالية (توليد + تدقيق) تخدم التوسّع دون إعادة هيكلة (§64).

## متى نعيد النظر (§61)
ننتقل إلى **Astro + Content Collections** فقط إذا تحقّق أحد:
- تجاوز عدد الصفحات قدرة الإدارة اليدوية (آلاف العناصر بمصادر مترابطة).
- الحاجة إلى أنواع محتوى متشعّبة (أسئلة/تصنيفات/باحثين) بعلاقات معقّدة.
- الحاجة لـ Build آمن متكرر بدل تعديل HTML مباشر.

في هذه الحالة: نفس الروابط تُحفظ، ويُبنى الموقع من نفس بيانات `seo/` دون فقدان صفحات مفهرسة.

## Cloudflare
لا يُضاف الآن. يُدرس فقط عند الحاجة إلى وظائف server-side (بحث API، لوحة تحكم، D1/KV/R2) (§20، §67).
